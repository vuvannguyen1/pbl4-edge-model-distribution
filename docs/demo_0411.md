# Kịch bản demo chiều 04/11

Tài liệu cho người trình bày. Mọi bước đều xem được trên giao diện: **dashboard** (máy S) và
**giao diện client** (laptop A, laptop B, điện thoại). Lệnh chạy bằng `cmd` trên Windows, ở thư
mục gốc repo. Ảnh minh hoạ trong [demo_screenshots/](demo_screenshots/) được chụp từ lần chạy thử
ngày 03/11, ở 1366×768 (laptop) và 390×844 (điện thoại).

| Máy | Vai trò | Chạy gì |
|---|---|---|
| S | Server + dashboard (máy chiếu) | `uvicorn server.main:app`, mở `http://127.0.0.1:8000/` |
| A | Client chia sẻ P2P | `client.web_ui --peer-port 9000` (hoặc `client.agent --serve`) |
| B | Client tải một phần từ A | `client.web_ui --host 0.0.0.0` |
| Điện thoại | Chọn/chụp ảnh qua trình duyệt | Mở giao diện client của laptop B |

A và B phải **cùng lớp thiết bị** (cùng hệ điều hành, loại CPU, nhóm RAM) thì mới chia sẻ cho
nhau. Xem lớp ở dashboard → **Thiết bị & P2P**.

## 1. Chuẩn bị trước giờ demo

### 1.1. Code và thư viện (cả 3 máy)

```cmd
:: nhánh có các thay đổi demo: vu (hoặc dev sau khi PR đã merge)
git checkout vu
git pull
pip install -e .[dev]
chcp 65001
python -m pytest -q
python tools\protocol\validate_examples.py
```

`pytest` phải xanh hết, `validate_examples` in `11/11 file mẫu hợp lệ`.

### 1.2. Model và thư mục dữ liệu riêng cho buổi demo (máy S)

Thêm model và bật/tắt variant đều **ghi vào Registry và Model Store**. Vì vậy buổi demo chạy trên
bản sao trong `data_demo\` (đã có trong `.gitignore`), không đụng `registry\model_registry.json`
hay `models\` của repo:

```cmd
python tools\download_models.py
python tools\build_registry.py
python tools\download_assets.py
mkdir data_demo
copy registry\model_registry.json data_demo\model_registry.json
robocopy models data_demo\models /E
```

`build_registry` phải in `4 variant, 4 ready`. Muốn làm lại từ đầu thì xoá `data_demo` rồi chạy
lại ba lệnh cuối.

### 1.3. Mạng: hotspot, IP, tường lửa

1. Bật **Mobile Hotspot** trên máy S. Laptop A, B và điện thoại kết nối vào hotspot này.
2. Tìm IP của máy S trên hotspot (thường là `192.168.137.1`):

   ```cmd
   ipconfig
   ```

   Tìm mục `Wireless LAN adapter Local Area Connection* <số>`, dòng `IPv4 Address`. Hoặc dùng
   PowerShell:

   ```powershell
   Get-NetIPAddress -AddressFamily IPv4 | Where-Object IPAddress -like "192.168.137.*" | Select-Object IPAddress, InterfaceAlias
   ```

   Làm tương tự trên laptop B để lấy `B_IP` (điện thoại sẽ mở `http://B_IP:8080`).
3. Mở cổng (PowerShell **Run as Administrator**):

   ```powershell
   # máy S
   New-NetFirewallRule -DisplayName "PBL4 server 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Any
   # laptop A và B: cổng P2P
   New-NetFirewallRule -DisplayName "PBL4 peer 9000" -Direction Inbound -Protocol TCP -LocalPort 9000 -Action Allow -Profile Any
   # laptop B: giao diện client cho điện thoại
   New-NetFirewallRule -DisplayName "PBL4 client 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Any
   ```

4. Kiểm tra từ A và B (kết quả phải là `TcpTestSucceeded : True`):

   ```powershell
   Test-NetConnection 192.168.137.1 -Port 8000
   ```

## 2. Lệnh chạy

Thay `S_IP` bằng IP ở mục 1.3.

> **Quan trọng:** mọi client **không chạy trên chính máy S** phải dùng
> `--server http://S_IP:8000`, **không dùng** `127.0.0.1` hay `localhost`. Giao diện client mở
> dashboard bằng đúng địa chỉ này (nút **Mở dashboard**, mã Request, tên model). Nếu ghi
> `127.0.0.1` mà mở trang client từ thiết bị khác (ví dụ điện thoại), các liên kết đó bị làm mờ
> kèm ghi chú "Chạy web_ui với --server http://<IP server>:8000 để mở dashboard từ thiết bị này".
> Chỉ client chạy ngay trên máy S mới được dùng `--server http://127.0.0.1:8000`.

**Máy S, phần 1 (P2P):** giới hạn tốc độ server 2000 kbps để thấy rõ phần tải từ peer nhanh hơn.

```cmd
set PBL4_DATA_DIR=data_demo
set PBL4_REGISTRY_PATH=data_demo\model_registry.json
set PBL4_MODEL_STORE=data_demo\models
set PBL4_RATE_LIMIT_KBPS=2000
set PBL4_LATENCY_SLO_MS=50
python -m uvicorn server.main:app --host 0.0.0.0 --port 8000
```

Dòng log cuối phải có `Server sẵn sàng: protocol 1.0, 4 variant ready ... giới hạn tốc độ 2000 kbps`.
Mở dashboard trên máy chiếu: `http://127.0.0.1:8000/`.

**Laptop A:**

```cmd
python -m client.web_ui --server http://S_IP:8000 --device-id laptopA --peer-port 9000 --open
```

**Laptop B** (mở cho điện thoại dùng chung):

```cmd
python -m client.web_ui --server http://S_IP:8000 --device-id laptopB --host 0.0.0.0 --open
```

**Điện thoại:** mở `http://B_IP:8080`. Ảnh chụp/chọn trên điện thoại được gửi lên laptop B và
nhận diện trên laptop B. Vì laptop B chạy với `--server http://S_IP:8000`, điện thoại bấm
**Mở dashboard** cũng mở được dashboard của máy S (điện thoại phải cùng hotspot).

Thay cho giao diện, laptop A có thể chạy agent dòng lệnh rồi ở lại chia sẻ:

```cmd
python -m client.agent --server http://S_IP:8000 --device-id laptopA --peer-port 9000 --image samples\dog.jpg --serve
```

## 4. Kịch bản P2P và số liệu so sánh

Cách chạy: phần 1 ở mục 2. Server giới hạn 2000 kbps, laptop A tải trước và ở lại chia sẻ, sau đó
laptop B xin cùng model. Server lập plan chia đôi: một nửa số miếng lấy từ A (qua mạng nội bộ,
không bị giới hạn), nửa còn lại lấy từ server.

| Lần chạy | Model | laptop A (chỉ server) | laptop B (peer + server) | Ghi chú |
|---|---|---|---|---|
| Chạy thử của nhóm ngày 03/11 (agent `--serve` + web_ui, hộp cát, 2000 kbps) | 4 miếng (khớp `mobilenetv2_int8`, 3,5 MB) | 14,8 s | 6,4 s (2 miếng peer + 2 miếng server) | `/admin-api/summary` khớp số miếng |
| Chạy thử tự động ngày 03/11 (cùng một máy, loopback, 2000 kbps) | `mobilenetv2_fp32`, 14 miếng | 56,2 s (14 miếng server) | 27,2 s (7 peer + 7 server) | `chunks_actual`: server 21, peer 7; ảnh 01–07 |

Lần nào laptop B cũng nhanh gấp khoảng 2,1–2,3 lần, vì chỉ còn một nửa số miếng phải đi qua
đường server bị giới hạn. Model chọn được phụ thuộc băng thông đo được và hạn tải 60 s: ở
2000 kbps Selector loại `resnet50_*` vì không tải kịp hạn.

Câu nói khi trình bày: "Cùng một model, laptop B tải trong khoảng một nửa thời gian của laptop A,
vì 7/14 miếng lấy thẳng từ laptop A. Mỗi miếng vẫn được kiểm SHA-256; miếng peer lỗi thì tự lấy
lại từ server."

## 5. Kịch bản server đề xuất đổi model (switch)

Server so latency client đo được với ngưỡng `PBL4_LATENCY_SLO_MS`. Vượt ngưỡng thì đề xuất bản nhỏ
hơn có top-1 cao nhất, và giao diện client hiện nút **Tải bản đề xuất**.

**Chọn ngưỡng theo số đo trên chính máy demo.** Trên laptop chạy thử ngày 03/11, `resnet50_fp32`
đo 28–50 ms (dao động giữa các lần) và `resnet50_int8` khoảng 17 ms. Với `PBL4_LATENCY_SLO_MS=50`,
server **thường giữ nguyên** model (lần đo 38,4 ms: "không vượt ngưỡng 50 ms"). Cách chọn:

1. Chạy phần 2 với `50` như dưới đây, nhận diện một lần với `resnet50_fp32`, đọc dòng
   **Latency (trung vị)** trên thẻ kết quả.
2. Nếu thẻ kết quả ghi "Giữ model này", đặt ngưỡng nằm giữa latency của int8 và fp32. Trên máy
   chạy thử dùng `20` thì lần nào cũng ra đề xuất.

Máy S: Ctrl+C server phần 1, rồi chạy lại **không giới hạn tốc độ** (tải `resnet50_fp32` 98 MB mất
vài giây):

```cmd
set PBL4_RATE_LIMIT_KBPS=
set PBL4_LATENCY_SLO_MS=50
python -m uvicorn server.main:app --host 0.0.0.0 --port 8000
```

Trên laptop B:

1. Chọn ảnh `dog.jpg`; ô **Model muốn dùng** chọn `resnet50_fp32`; mở **Tuỳ chọn khi xin model**,
   tick "Hỏi server dù máy đã có model" → **Nhận diện**.
2. Kết quả: badge "Đề xuất đổi sang resnet50_int8", phần **Lý do** ghi rõ latency, ngưỡng và kích
   thước hai bản (số định dạng kiểu Việt Nam: `50,3 ms`, `97,8 MB`, `top-1 74,8 %`).
3. Bấm **Tải bản đề xuất (resnet50_int8)**: chạy lại đúng ảnh cũ, tải 25 miếng, kết quả mới
   "Giữ model này" với latency thấp hơn (lần chạy thử: 50,3 ms → 17,1 ms).

Khởi động lại server làm mất danh sách thiết bị và lượt tải trong RAM. Client tự đăng ký lại ở lần
nhận diện kế tiếp, và Registry, CSDL, feedback trong `data_demo` vẫn còn.

## 6. Phương án dự phòng

| Sự cố | Cách xử lý nhanh |
|---|---|
| Hotspot chặn client với client (P2P luôn lấy từ server) | Chạy cả A và B trên **máy S** với hai cổng peer khác nhau (`--peer-port 9000` và `--peer-port 9100`, B dùng `--port 8081`). Lần chạy thử tự động làm đúng cách này (loopback). |
| A và B khác lớp thiết bị nên không chia sẻ | Như trên: chạy cả hai client trên cùng một máy |
| Laptop không vào được `S_IP:8000` | Kiểm tra `ipconfig`, tường lửa (mục 1.3), `Test-NetConnection`. Vẫn lỗi thì chạy toàn bộ trên máy S với `--server http://127.0.0.1:8000` |
| Liên kết sang dashboard bị làm mờ trên client | Client đang chạy với `--server http://127.0.0.1:8000` nhưng trang được mở từ thiết bị khác: chạy lại web_ui với `--server http://S_IP:8000` (mục 2). Xem ảnh [16](demo_screenshots/16-dien-thoai-lien-ket-lam-mo-390.png) |
| Điện thoại không mở được `B_IP:8080` | Kiểm tra laptop B chạy với `--host 0.0.0.0` và đã mở cổng 8080. Không được thì dùng chế độ điện thoại của Chrome DevTools (Ctrl+Shift+M) hoặc ảnh 08–10 |
| Không ra đề xuất đổi model | Hạ `PBL4_LATENCY_SLO_MS` (mục 5) rồi khởi động lại server |
| Upload báo "Trùng file" | Đổi tên file `.onnx` (mỗi variant một file) |
| Upload báo lỗi ONNX | File hỏng hoặc không phải ONNX; server không lưu gì, chọn file khác |
| Lỡ tắt nhầm variant | Bấm **Bật** trên cùng dòng |
| Dashboard hiện "Mất kết nối server" | Server đã tắt hoặc lỗi; xem cửa sổ uvicorn, chạy lại lệnh ở mục 2. Dữ liệu đang hiện được giữ nguyên |
| Giao diện client lỗi | Dùng `client.agent` dòng lệnh (mục 2) và [lenh.md](../lenh.md); dashboard vẫn hiện đủ |
| Muốn làm lại sạch | Ctrl+C mọi tiến trình, `rmdir /s /q data_demo`, làm lại mục 1.2 |
| Mọi thứ đều hỏng | Trình bày bằng ảnh trong [demo_screenshots/](demo_screenshots/) theo thứ tự bảng mục 3 |
